# 需求文档 - 匿名情绪日记应用

## 介绍

匿名情绪日记应用是一个面向校园内学生的日记平台。用户可以匿名登录、发布日记、查看历史日记，系统通过情绪检测算法分析日记内容的情绪状态，并对高风险情绪进行提示和预警。应用采用 C# .NET 技术栈和本地数据库存储。

## 术语表

- **系统**: 匿名情绪日记应用
- **用户**: 校园内的学生，通过匿名账户访问系统
- **日记**: 用户发布的文本内容，包含时间戳和情绪标签
- **情绪检测**: 通过关键词识别和开源大模型接口分析日记内容的情绪状态
- **情绪指数**: 表示日记情绪程度的数值，范围 0-100，数值越高表示情绪越负面
- **高风险情绪**: 情绪指数超过设定阈值（如 70）的日记内容
- **匿名账户**: 不需要真实身份信息的用户账户，仅需用户名和密码
- **本地数据库**: C# 应用内置的数据库，用于存储用户和日记数据

## 需求

### 需求 1：用户认证与账户管理

**用户故事**: 作为一名学生，我想要创建匿名账户并登录系统，以便安全地记录我的日记。

#### 验收标准

1. 当用户提交注册表单时，系统应验证用户名长度在 3-20 个字符之间
2. 当用户提交注册表单时，系统应验证密码长度至少为 8 个字符
3. 当用户提交注册表单时，系统应检查用户名是否已存在于数据库中
4. 当用户名和密码验证通过时，系统应在本地数据库中创建新用户账户
5. 当用户输入正确的用户名和密码时，系统应允许用户登录
6. 当用户输入错误的用户名或密码时，系统应拒绝登录并显示错误提示

### 需求 2：日记发布与存储

**用户故事**: 作为一名学生，我想要发布日记并将其保存到系统中，以便记录我的日常情绪和想法。

#### 验收标准

1. 当用户登录后访问发布日记页面时，系统应显示日记编辑界面
2. 当用户输入日记内容并点击发布时，系统应验证日记内容不为空
3. 当用户输入日记内容并点击发布时，系统应验证日记内容长度不超过 5000 个字符
4. 当日记内容验证通过时，系统应在本地数据库中保存日记，包含用户 ID、内容、时间戳和情绪指数
5. 当日记保存成功时，系统应返回成功提示并清空编辑框

### 需求 3：情绪检测与分析

**用户故事**: 作为一名学生，我想要系统分析我日记的情绪状态，以便了解我的情绪变化趋势。

#### 验收标准

1. 当用户发布日记时，系统应使用关键词识别算法分析日记内容中的情绪关键词
2. 当关键词识别完成时，系统应调用开源大模型接口进行深层情绪分析
3. 当情绪分析完成时，系统应生成 0-100 范围内的情绪指数
4. 当情绪指数生成后，系统应将其与日记一起保存到数据库
5. 当用户查看日记时，系统应显示该日记对应的情绪指数

### 需求 4：高风险情绪预警

**用户故事**: 作为一名学生，我想要在发布高风险情绪日记时收到系统提示，以便及时寻求帮助。

#### 验收标准

1. 当日记的情绪指数超过 70 时，系统应识别为高风险情绪
2. 当检测到高风险情绪时，系统应在发布成功后显示预警提示
3. 当检测到高风险情绪时，系统应在预警提示中提供心理援助资源链接或联系方式
4. 当用户查看历史日记时，系统应用不同的视觉标记（如红色标签）标识高风险日记

### 需求 5：日记查看与历史记录

**用户故事**: 作为一名学生，我想要查看我的历史日记和情绪趋势，以便反思我的情绪变化。

#### 验收标准

1. 当用户登录后访问日记列表页面时，系统应显示该用户的所有日记
2. 当显示日记列表时，系统应按发布时间倒序排列日记
3. 当用户点击某篇日记时，系统应显示该日记的完整内容、发布时间和情绪指数
4. 当用户查看日记列表时，系统应显示每篇日记的摘要（前 100 个字符）
5. 当用户查看日记列表时，系统应提供删除日记的功能

### 需求 6：系统日志与分析

**用户故事**: 作为开发人员，我想要记录系统的调试日志、错误异常和情绪分析结果，以便进行系统调试和故障排查。

#### 验收标准

1. 当系统执行调试操作时，系统应记录调试信息、时间戳和相关上下文到调试日志文件
2. 当系统发生错误时，系统应记录错误类型、错误信息和堆栈跟踪到错误异常日志文件
3. 当情绪检测完成时，系统应记录检测结果、情绪指数、分析时间和使用的模型版本到情绪分析日志文件
4. 当日志文件大小超过 10MB 时，系统应自动创建新的日志文件并归档旧文件
