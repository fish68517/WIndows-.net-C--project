# 基于深度学习的网络异常流量检测系统开发指南

## 1. 项目目标

本项目依据 `doc/需求.txt` 的要求，开发一个使用 C 语言实现的网络异常流量检测系统。系统应能够基于公开网络流量数据集完成模型训练和验证，并对输入的网络流量记录进行异常判断和报警输出。

本项目交付形态为 Windows 可执行文件 `network_anomaly_detector.exe`，便于复制到老师的机器上直接运行。

## 2. 需求分析

### 2.1 背景

网络异常流量可能造成网络拥塞、服务中断或数据泄露。传统规则和固定阈值方法对复杂攻击适应能力较弱，因此需求文档要求使用深度学习模型自动提取流量特征并识别异常流量。

### 2.2 功能要求

系统需要实现以下功能：

1. 使用合适的深度学习模型进行网络异常检测。
2. 使用公开数据集进行训练和验证，例如 UNSW-NB15 或 CAIDA。
3. 支持对网络流量记录进行实时分析。
4. 发现异常流量时输出报警信息。
5. 输出实验报告所需的训练过程、检测结果和评价指标。

### 2.3 开发约束

1. 编程语言：C 语言。
2. 开发工具：在线 C 语言开发编辑器。
3. 交付文件：Windows `.exe` 可执行文件。
4. 运行方式：老师机器上无需安装大型深度学习框架，复制程序和必要数据文件即可运行。

## 3. 技术路线

### 3.1 推荐模型：自编码器

需求文档提到可选择自编码器或 GAN。考虑到项目要求使用 C 语言实现，并且需要打包为便携式 exe，推荐采用轻量级全连接自编码器。

选择自编码器的原因：

1. 结构清晰，适合用 C 语言手写前向传播、反向传播和模型保存。
2. 异常检测逻辑简单，通过重构误差判断流量是否异常。
3. 不依赖 TensorFlow、PyTorch 等大型框架，便于打包和移植。
4. 适合课程设计展示，能够清楚说明模型选择、数据预处理、训练过程和检测结果。

### 3.2 自编码器结构

建议模型结构如下：

```text
输入层：n 个归一化后的流量特征
隐藏层1：32 个神经元，ReLU 激活
瓶颈层：8 个神经元，ReLU 激活
隐藏层2：32 个神经元，ReLU 激活
输出层：n 个神经元，线性输出
损失函数：均方误差 MSE
异常判定：重构误差 > 阈值则判定为异常
```

其中 `n` 为最终保留的数值特征数量。为了降低 C 语言实现复杂度，建议优先选择 10 到 20 个数值型流量特征，避免直接处理大量字符串型字段。

### 3.3 系统处理流程

```text
读取 CSV 流量数据
        |
字段筛选与数值转换
        |
特征归一化
        |
自编码器训练或加载模型
        |
计算每条流量记录的重构误差
        |
根据阈值判断正常/异常
        |
输出检测结果和报警信息
```

## 4. 数据集方案

### 4.1 推荐数据集：UNSW-NB15

优先推荐使用 UNSW-NB15 数据集。该数据集提供训练集和测试集文件，包含正常流量和多种攻击类型，适合课程设计使用。

当前工程中有三类数据目录：

1. `data/processed/UNSW-NB15-demo/`：课堂演示子集，默认加载，运行速度最快。
2. `data/processed/UNSW-NB15/`：处理后的全量公开数据集，带表头、逗号分隔，推荐正式运行使用。
3. `data/raw/UNSW-NB15/`：原始下载文件，无表头、制表符分隔。程序已支持直接加载，但讲解和演示优先使用处理后目录。

建议使用文件：

1. `UNSW_NB15_training-set.csv`：训练模型。
2. `UNSW_NB15_testing-set.csv`：测试模型。

为了便于在线 C 编辑器调试，建议先从训练集中截取小样本：

```text
data/train_small.csv      训练样本，建议 1000 到 5000 行
data/test_small.csv       测试样本，建议 500 到 2000 行
data/realtime_sample.csv  模拟实时检测输入
```

完整数据集可在最终实验阶段使用。

### 4.2 特征选择

建议选择数值字段作为输入特征，例如：

```text
dur, spkts, dpkts, sbytes, dbytes, rate, sttl, dttl,
sload, dload, sloss, dloss, sinpkt, dinpkt, sjit, djit
```

如果 CSV 字段名与实际下载文件不完全一致，应以实际数据集表头为准。对于 `data/raw/UNSW-NB15/`，原始文件没有表头，程序按 UNSW-NB15 固定字段位置读取上述 16 个数值特征和 `label` 标签。

### 4.3 标签使用方式

训练自编码器时建议只使用正常流量训练，使模型学习正常流量模式。

测试时使用数据集中的 `label` 字段进行评价：

```text
label = 0 表示正常流量
label = 1 表示异常或攻击流量
```

模型推理阶段不使用标签，只根据重构误差判断是否异常。

## 6. 模块设计

### 6.1 `main.c`

负责解析命令行参数，并调用训练、测试或实时检测流程。

建议支持以下命令：

```text
network_anomaly_detector.exe train data/train_small.csv
network_anomaly_detector.exe test data/test_small.csv
network_anomaly_detector.exe detect data/realtime_sample.csv
```

### 6.2 `csv_loader`

负责读取数据文件，完成格式识别、表头解析、字段定位和数据装载。

主要职责：

1. 打开数据文件。
2. 优先按带表头 CSV 解析，按字段名定位 `dur`、`spkts`、`dpkts` 等 16 个特征。
3. 如果没有识别到表头，则判断是否为 raw UNSW-NB15 的无表头 TSV 格式。
4. 对 raw UNSW-NB15 使用固定列号读取 16 个特征，并读取最后一列 `label`。
5. 将每条记录转换为浮点特征数组。
6. 跳过空行、非法行或字段缺失行。
7. 将识别到的数据格式写入 `output/app.log`，便于排查数据加载失败原因。

### 6.3 `preprocess`

负责数据预处理。

主要职责：

1. 计算训练集每个特征的最小值和最大值。
2. 使用 Min-Max 归一化将特征缩放到 0 到 1。
3. 保存归一化参数到 `model/normalize_params.txt`。
4. 测试和检测阶段加载相同归一化参数。

归一化公式：

```text
x_norm = (x - min) / (max - min)
```

当 `max == min` 时，该特征归一化结果设为 0。

### 6.4 `autoencoder`

负责自编码器模型训练、推理、保存和加载。

主要职责：

1. 初始化网络权重。
2. 实现前向传播。
3. 计算重构误差。
4. 实现反向传播和参数更新。
5. 保存模型到 `model/autoencoder_model.bin`。
6. 从模型文件加载权重。

建议训练参数：

```text
epoch = 50
learning_rate = 0.001
batch_size = 32
threshold_percentile = 95
```

### 6.5 `detector`

负责异常判断和报警输出。

主要职责：

1. 对输入流量记录调用自编码器推理。
2. 计算每条记录的重构误差。
3. 与阈值比较。
4. 输出检测结果到 `output/detect_result.csv`。
5. 对异常记录写入 `output/alarm_log.txt`，并在控制台显示报警。

报警示例：

```text
[ALARM] record=125 error=0.0842 threshold=0.0500 status=ANOMALY
```

## 7. 在线 C 语言开发工具

### 7.1 推荐开发工具

推荐使用 OnlineGDB 的 C 语言在线编译调试环境进行初期开发和单文件调试。

使用方式：

1. 打开 OnlineGDB。
2. 选择语言为 C。
3. 先将核心逻辑写在单个 `main.c` 中调通。
4. 确认 CSV 读取、归一化和模型推理正确后，再拆分为多个 `.c` 和 `.h` 文件。
5. 使用小样本 CSV 文件进行在线调试，避免在线环境内存或运行时间不足。

注意：很多在线 C 编辑器默认生成 Linux 可执行程序，并不直接生成 Windows `.exe`。因此在线编辑器用于开发和调试，最终 exe 需要使用 Windows 目标环境编译。

### 7.2 在线生成 exe 的推荐方式

为了保持“在线开发”和“exe 交付”两项要求都能满足，本项目采用以下流程：

```text
OnlineGDB 编写和调试 C 源码
        |
下载源码到 Windows 机器
        |
使用 MinGW-w64 编译
        |
生成 network_anomaly_detector.exe
        |
下载 exe 并与 data/model/output 目录一起打包
```

如果本机 PowerShell 禁止运行 `.ps1` 脚本，可使用 `build.bat` 或直接执行 `gcc` 编译命令。

## 8. Windows exe 编译打包

### 8.1 编译命令

如果使用 MinGW-w64，可使用以下命令：

```powershell
gcc src/main.c src/app_paths.c src/csv_loader.c src/preprocess.c src/autoencoder.c src/detector.c src/gui.c src/logger.c -O2 -std=c11 -Wall -Wextra -static -static-libgcc -mwindows -o build/network_anomaly_detector.exe -lm -luser32 -lgdi32 -lshell32 -lole32
```

### 8.2 本项目编译脚本

本项目提供两个 MinGW-w64 编译入口。

PowerShell 允许执行脚本时使用：

```powershell
.\build.ps1
```

如果 PowerShell 禁止执行脚本，使用批处理：

```powershell
.\build.bat
```

两个脚本最终都会生成：

```text
build/network_anomaly_detector.exe
```

## 9. 开发步骤

### 9.1 第一步：准备数据

1. 下载 UNSW-NB15 数据集。
2. 选择训练集和测试集 CSV。
3. 提取小样本文件，便于在线编辑器调试。
4. 确认字段名、标签列和特征列。

### 9.2 第二步：实现 CSV 读取

1. 读取表头。
2. 解析每一行 CSV。
3. 提取指定数值特征。
4. 将标签保存为整数，用于测试评价。

验收标准：

```text
程序能够打印前 5 条记录的特征值和标签。
```

### 9.3 第三步：实现归一化

1. 训练阶段计算每个特征的最小值和最大值。
2. 保存归一化参数。
3. 测试和检测阶段加载归一化参数。

验收标准：

```text
所有输入特征归一化后位于 0 到 1 之间。
```

### 9.4 第四步：实现自编码器

1. 定义网络层结构。
2. 实现 ReLU、线性输出和 MSE。
3. 实现前向传播。
4. 实现反向传播。
5. 输出每个 epoch 的平均损失。

验收标准：

```text
训练损失整体下降，并生成 autoencoder_model.bin。
```

### 9.5 第五步：确定异常阈值

1. 使用正常训练样本计算重构误差。
2. 将误差从小到大排序。
3. 取第 95 百分位作为异常阈值。
4. 保存阈值到模型文件或单独配置文件。

验收标准：

```text
程序输出 threshold，并能在测试阶段加载该阈值。
```

### 9.6 第六步：测试与评价

测试集包含正常和异常样本。系统应输出以下指标：

```text
TP：异常样本被正确识别为异常
TN：正常样本被正确识别为正常
FP：正常样本被误报为异常
FN：异常样本被漏报为正常
Accuracy = (TP + TN) / 总样本数
Precision = TP / (TP + FP)
Recall = TP / (TP + FN)
F1 = 2 * Precision * Recall / (Precision + Recall)
```

验收标准：

```text
程序能够输出混淆矩阵、Accuracy、Precision、Recall 和 F1。
```

### 9.7 第七步：模拟实时检测

课程设计中可使用循环读取 CSV 的方式模拟实时流量输入。

实现方式：

1. 每隔固定时间读取一条记录。
2. 对记录进行归一化。
3. 调用模型推理。
4. 如果异常则立即输出报警。

验收标准：

```text
控制台能够持续输出检测状态，异常记录能够写入 alarm_log.txt。
```

### 9.8 第八步：打包 exe

1. 在 Windows 编译环境生成 `network_anomaly_detector.exe`。
2. 将 exe、模型文件、样本数据和 README 放入发布目录。
3. 在另一台 Windows 机器上测试运行。

验收标准：

```text
双击或命令行运行 exe 后，能够完成检测并生成结果文件。
```

## 12. 风险与处理方案

### 12.1 在线编辑器无法处理完整数据集

处理方案：

1. 在线调试阶段使用小样本。
2. 完整数据集训练放到本地 Windows + MinGW-w64 编译环境执行。
3. 程序设计时支持分批读取，避免一次性加载全部 CSV。

### 12.2 在线编辑器无法直接导出 exe

处理方案：

1. 在线编辑器负责 C 代码开发和调试。
2. 使用 MinGW-w64 生成 exe。
3. 在报告中说明 exe 是由同一份 C 源码编译得到。

### 12.3 C 语言实现深度学习工作量较大

处理方案：

1. 使用轻量级全连接自编码器，不使用复杂 CNN、RNN 或 GAN。
2. 固定网络层数，减少动态结构。
3. 优先保证完整流程可运行，再优化模型指标。

### 12.4 老师机器缺少运行环境

处理方案：

1. 使用静态或低依赖方式编译 exe。
2. 不依赖 Python、CUDA、TensorFlow、PyTorch。
3. 将模型文件和样本数据一起放入发布目录。
