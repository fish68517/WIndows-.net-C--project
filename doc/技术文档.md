# 匿名情绪日记系统技术文档

## 1. 项目定位

本项目是一个基于 WinForms + SQLite 的桌面端匿名情绪日记系统，核心目标是帮助用户记录日记、自动识别情绪风险，并为管理员提供跨用户的情绪监测和人工干预支持能力。

本次答辩版本在原有基础上新增了三类关键能力：

1. 基于用户全部笔记的 AI 聚合情绪画像
2. 管理员账户、情绪监控台与联系记录
3. 界面重构与视觉优化

## 2. 技术栈

- 开发语言：C#
- 框架：.NET 8.0 Windows Forms
- 数据库：SQLite
- 加密：BCrypt.Net-Next
- JSON 处理：Newtonsoft.Json
- 大模型接入：本地 LLM 接口（默认配置为 Ollama `http://localhost:11434/api/generate`）

## 3. 分层结构

项目整体采用轻量分层设计，目录结构如下：

### 3.1 核心目录

- `Models`
  - 实体模型层，定义 `User`、`Diary`、`AdminContactRecord`、`UserEmotionProfile`
- `DAOs`
  - 数据访问层，负责 SQLite 的增删改查
- `Services`
  - 业务层，负责认证、日记处理、情绪分析、管理员统计等
- `Views`
  - WinForms 界面层，负责登录、注册、日记列表、详情、管理员工作台等页面
- `Controllers`
  - 早期控制器实现，当前项目中部分页面已直接调用 Service 层

### 3.2 当前业务流说明

当前版本中，真正承担主业务的是 `Service + View` 组合：

1. `View` 接收用户操作
2. `Service` 完成业务处理
3. `DAO` 负责持久化
4. `Model` 负责数据承载

控制器文件仍保留，主要用于体现 MVC 结构，但项目运行时主要由视图直接驱动服务层。

## 5. 核心模块说明

### 5.1 DatabaseManager

`DatabaseManager` 负责项目启动时自动初始化数据库，并完成以下工作：

1. 自动创建数据库文件
2. 自动创建缺失表
3. 自动补齐 `Users` 表中的新增字段
4. 自动创建默认管理员账号

默认管理员信息来自 `app.config`：

- 用户名：`admin`
- 密码：`Admin@12345`

说明：登录界面答辩提示文案中使用了小写展示，实际数据库初始化以配置文件为准。

### 5.2 UserService

主要职责：

1. 用户注册
2. 用户登录
3. 用户名与密码校验
4. 拉取普通用户列表

注册时支持额外录入联系方式，便于后续管理员人工联系。

### 5.3 DiaryService

主要职责：

1. 发布日记
2. 校验日记内容长度
3. 自动调用情绪分析服务
4. 删除与查询日记

本次修复的关键点：

- 原项目 `DiaryService()` 默认未注入情绪分析服务，导致单篇日记分析可能未真正执行
- 当前版本已改为默认注入 `EmotionDetectionService`

### 5.4 EmotionDetectionService

该服务是本次升级的核心。

#### 单篇日记分析策略

对用户新写的一篇日记执行两阶段分析：

1. 关键词分析
   - 通过正负向情绪词典估计情绪强度
2. 大模型分析
   - 调用本地 LLM 输出 0-100 的情绪指数

最终结果采用加权融合：

- 关键词：40%
- LLM：60%

如果本地模型不可用，则自动回退到关键词分析，保证系统不因模型离线而失效。

#### 用户全量日记聚合画像

新增 `AnalyzeUserEmotionProfile(User user, IEnumerable<Diary> diaries)`：

1. 统计全部日记数量、平均情绪指数、最近一次情绪指数、高风险日记数量
2. 构建用户全量历史摘要
3. 调用 LLM 输出：
   - `overallEmotionIndex`
   - `riskLevel`
   - `summary`
   - `suggestedAction`
4. 若 LLM 不可用，退回启发式算法生成用户画像

这一功能正对应答辩需求中的“AI 分析用户所有笔记来分析情绪”。

### 5.5 AdminService

新增管理员业务服务，负责：

1. 获取所有普通用户
2. 汇总所有用户日记
3. 为每个用户生成聚合情绪画像
4. 保存管理员联系记录
5. 读取联系历史

管理员工作台所展示的所有关键数据都由该服务统一提供。

## 8. 项目运行说明

### 8.1 构建命令

```powershell
dotnet build "作业-windows.Net项目.sln"
```

### 8.2 运行说明

直接启动桌面程序后：

1. 普通用户登录进入日记工作台
2. 管理员登录进入管理员情绪监控台

### 8.3 默认演示路径

1. 注册普通用户
2. 写入多篇不同情绪的日记

4. 使用管理员账号登录
5. 查看该用户总情绪指数
6. 记录一次联系动作

## 9. 安全与局限

### 9.1 已实现的安全措施

- 密码采用 BCrypt 哈希保存
- SQLite 查询使用参数化，避免 SQL 注入
- 本地模型调用失败时有回退逻辑

### 9.2 当前局限

1. 联系用户功能目前是“查看联系方式 + 记录联系行为”，不直接发送短信或邮件
2. 本地模型输出质量依赖答辩机器上的模型能力
3. 控制器层历史代码仍保留，后续可继续统一到 View-Service 模式

## 10. 可答辩亮点总结

本项目的技术亮点主要有四个：

1. 使用本地 LLM 完成单篇与全量两级情绪分析
2. 通过启发式回退保证模型异常时系统仍可工作
3. 在桌面端实现管理员跨用户情绪监测与人工干预留痕
4. 对原始 WinForms 页面进行统一主题化重构，提升展示效果
